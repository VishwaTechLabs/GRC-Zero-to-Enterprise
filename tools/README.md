# GRC Tools & Technology Map

Tools are taught as examples of where technology supports a GRC process. Tool names do
not replace understanding of the underlying risk/control workflow.

| Category | Tools / technologies | GRC use |
|---|---|---|
| GRC platforms | ServiceNow GRC, Archer, IBM OpenPages, MetricStream, AuditBoard, OneTrust | Risks, controls, issues, assessments, workflows |
| AWS | Security Hub, Config, Audit Manager, CloudTrail, IAM, KMS, GuardDuty | Cloud evidence and security governance |
| Azure | Defender for Cloud, Azure Policy, Entra ID, Monitor | Cloud controls and identity evidence |
| GCP | Security Command Center, Cloud Audit Logs, IAM, Organization Policy | Cloud governance and evidence |
| IAM/IGA | SailPoint, Saviynt, Okta, Entra ID | Access governance and lifecycle |
| PAM | CyberArk, BeyondTrust | Privileged-access governance |
| SIEM/SOC | Splunk, Microsoft Sentinel, QRadar, Elastic | Monitoring, incidents and evidence |
| Endpoint | CrowdStrike, Microsoft Defender | Endpoint-control evidence |
| Vulnerability | Qualys, Tenable, Rapid7 | Vulnerability governance |
| AppSec | Burp Suite, SonarQube, Snyk, OWASP tooling | SDLC/AppSec control evidence |
| DevSecOps | GitHub Actions, Jenkins, Terraform, Docker, Kubernetes, Trivy | Pipeline/security governance |
| Cloud security | Wiz, Prisma Cloud | Cloud posture and risk visibility |
| OT security | Claroty, Nozomi Networks, Dragos, Defender for IoT, Tenable OT | OT asset and security visibility |
| Analytics | Excel, Power BI concepts | Risk and executive dashboards |

## Tool-lab rule
Students must explain **why** a tool is used, what risk it addresses, what control it
supports and what evidence it generates.
